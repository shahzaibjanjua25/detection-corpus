# Hypothesis: T1003.008 — /etc/shadow Read

## Statement
If an adversary has code execution on a Linux host at any privilege level
that can read /etc/shadow (root, or a misconfigured file permission), they
will extract password hashes for offline cracking. /etc/shadow is the single
highest-value file on the host after private keys: it yields every local
account's hash, which can be cracked at leisure and reused against other
hosts where users share passwords.

## Observable
An auditd PATH record naming /etc/shadow, /etc/gshadow, /etc/passwd,
/etc/group (or their backup variants) paired with a SYSCALL record for
open/openat/read/readv/pread64, where the reading process is not a
privileged consumer (sshd, login, sudo, passwd, PAM, sssd, systemd) and
not a routine system tool (getent, id, who, cat, grep, etc.).

## Why read, not write
Unlike the previous three rules, this fires on *access* to the file, not
modification. That means it catches the credential dump in progress — before
exfiltration — but at the cost of a much larger false-positive surface,
because every legitimate tool that touches user databases reads these files.
The filter list is therefore long and load-bearing; this is the noisiest
rule in the series so far and the one most likely to need per-fleet tuning.

## Telemetry prerequisite
auditd watch on credential files, e.g.:
  -w /etc/shadow -p r -k shadow_read
  -w /etc/shadow- -p r -k shadow_read
  -w /etc/gshadow -p r -k shadow_read
  -w /etc/gshadow- -p r -k shadow_read
  -w /etc/passwd -p r -k shadow_read
  -w /etc/passwd- -p r -k shadow_read
  -w /etc/group -p r -k shadow_read
  -w /etc/group- -p r -k shadow_read
Note: `-p r` is essential — a `-p wa` watch (like the previous rules) will
not fire on reads. Some auditd versions require both `-p r` and `-p w` to be
specified separately; verify on your kernel.

## Performance caveat
Watching /etc/passwd and /etc/group for reads is *high volume* on a busy
fleet — every `id`, `ls -l`, `ps`, and PAM decision touches them. If audit
throughput is a concern, start with only /etc/shadow and /etc/gshadow (much
lower volume) and expand to passwd/group once the FP filter is validated.
This is the first rule in the series where the audit watch itself has a
measurable cost.

## Known blind spots
- Hosts without auditd (eBPF-only) → does not fire. Pair with a Falco rule
  on `open_read` for the same paths.
- Reads performed through a privileged helper (setuid binary, PAM module,
  sssd) will attribute the reader to the helper, not the caller. This is
  the intended exclusion — but it also means an adversary who can invoke
  a legitimate privileged helper to read shadow on their behalf will evade.
- Containerised reads only surface if the host audit subsystem covers
  container namespaces.
- LDAP/SSSD-backed authentication → shadow may not be the credential store
  at all; needs a directory-server-side rule, out of scope here.
