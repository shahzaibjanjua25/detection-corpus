Promotion path: `experimental` → `test` after two weeks of shadow mode,
target < 3 FPs/day per 1,000 hosts (sudoers edits are rarer than cron
edits, so the FP budget is tighter). The package-manager filter is the
likely source of residual noise on Debian/Ubuntu fleets (dpkg maintainer
scripts spawn /bin/sh). Tune by adding a `ppid` allow-list for dpkg/apt
parent processes if FP rate is high. → `stable` once the config-management
filter is validated against the fleet's actual tooling paths and FP rate is
< 1/day. This rule is a candidate for `level: high` → `critical` promotion
if the fleet shows zero legitimate plain-editor edits of sudoers (i.e., all
admin edits go through visudo).
