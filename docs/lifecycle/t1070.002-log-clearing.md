# Lifecycle: proc_creation_lnx_log_clearing

| Date       | Status       | Change                                         | Justification |
|------------|--------------|------------------------------------------------|---------------|
| 2024-03-15 | experimental | Rule authored with auditd + process_creation   | Initial coverage, untested in production |

Promotion path: `experimental` → `test` after two weeks of shadow mode,
target < 3 FPs/day per 1,000 hosts. The primary FP source is **scheduled
logrotate** — logrotate's postrotate scripts spawn rm/truncate as child
processes, which the logrotate EXECVE filter does not catch (it filters
logrotate itself, not its children). Expect to add a `ppid` allow-list for
`logrotate` child processes during the test phase. Secondary FP source is
application-level rotation (nginx, Java appenders, Python handlers) that
unlinks its own logs — must be allow-listed per fleet by exe path.
→ `stable` once both filters are validated and FP rate is < 1/day. This is
the first rule in the series where the **promotion criterion includes a
verification step beyond FP rate**: a manual tabletop test confirming that
the auditd watch actually emits PATH records for `unlink` and `truncate`
on the fleet's kernel — this is not guaranteed across auditd/kernel
versions and must be verified, not assumed.
