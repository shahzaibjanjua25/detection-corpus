# Lifecycle: proc_creation_lnx_reverse_shell

| Date       | Status       | Change                                         | Justification |
|------------|--------------|------------------------------------------------|---------------|
| 2024-03-17 | experimental | Rule authored with process_creation selection  | Initial coverage, untested in production |

Promotion path: `experimental` → `test` after **one week** of shadow mode
(not two) — the FP surface is narrower than Days 1–6 and the severity of a
missed reverse shell justifies faster promotion. Target < 2 FPs/day per
1,000 hosts on production fleets; expect higher on dev/staging (allow to
run at `test` with a documented exception). → `stable` once the FP rate is
validated on production and the `filter_socat_legit` / `filter_netcat_listen`
filters are confirmed to be covering the fleet's legitimate use of socat
and nc (many shops use socat for legitimate service-relay purposes; the
listen-mode filter is load-bearing). **Verification step beyond FP rate:**
confirm the fleet's process-accounting pipeline actually captures command
line (not just process path) — some osquery and Sysmon-for-Linux
configurations omit `cmdline` due to performance concerns, which would
silently break this rule. This is the same class of verification
required for Day 6 (file_event schema check), but applied to command-line
capture.

**Severity exception for dev/staging:** the lifecycle document explicitly
allows dev and staging fleets to run this rule at `medium` severity with
a separate "development activity" tag, because the FP rate from
legitimate developer connectivity tests is expected to be high. Production
remains `critical`.

**Split candidate:** if the FP rate proves high, split into two rules:
(a) bash /dev/tcp + nc -e + socat EXEC (narrow, unambiguous, keep
`critical`), (b) python/perl/ruby/php socket one-liners (wider, more
ambient noise from legitimate scripting, demote to `high`). The split
preserves the `critical` tier for the highest-signal patterns without
losing coverage of the noisier interpreter paths.
